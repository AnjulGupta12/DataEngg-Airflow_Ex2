# Orders Data Processing Pipeline (Airflow Parameterized DAG & Dataproc)

## Overview

This project implements an automated, parameterized data pipeline using Google Cloud Composer (Apache Airflow) and Dataproc. The pipeline is designed to process daily order records (e.g., `orders_20260924.csv`) by running a PySpark job that filters for "Completed" orders. 

A key feature of this pipeline is its ability to handle **backfilling** via Airflow parameters, allowing users to manually pass a specific date or default to the current run date automatically.

## Pipeline Flow

The workflow is orchestrated by `airflow_orders_job.py` and executes in two primary tasks:

1.  **Task 1: Get Execution Date (`get_execution_date`)**
    *   A Python task extracts the user-provided date from the Airflow run parameters (`execution_date`).
    *   **Condition A:** If the user provides a specific date in `YYYYMMDD` format, the task fetches that date.
    *   **Condition B:** If no input is provided (defaults to `"NA"`), it automatically falls back to the Airflow current execution date (`ds_nodash`).
2.  **Task 2: Submit Spark Job (`submit_pyspark_job`)**
    *   Airflow pulls the resolved date from Task 1 using XComs.
    *   It submits the `orders_data_process.py` script to a running Dataproc cluster, passing the date dynamically as an argument (`--date=YYYYMMDD`).
    *   The PySpark job reads the corresponding daily file, filters for `order_status == "Completed"`, and writes the output back to GCS.

## Cloud Storage (GCS) Structure

This architecture relies on two distinct GCS buckets:

### 1. Airflow Environment Bucket (Auto-generated by Composer)
Contains the core Airflow directories:
*   `dags/`: Stores DAG files (e.g., `airflow_orders_job.py`). A monitoring script (`airflow_monitoring.py`) can be used here to detect and parse new files so they appear in the Airflow Web UI.
*   `data/`, `logs/`, `plugins/`

### 2. Project Data Bucket (`airflow-test-projects-gds-dev`)
A self-made bucket to store source data and processing scripts:
```text
gs://airflow-test-projects-gds-dev/
└── airflow-project-2/
    ├── data/
    │   ├── orders_20260922.csv     
    │   ├── orders_20260923.csv     
    │   └── orders_20260924.csv     
    ├── output/                     # Destination for processed orders
    └── spark_code/
        └── orders_data_process.py  # PySpark script
```

## Step-by-Step Setup and Execution

**Step 1: Set Up Storage and Code**
*   Create the bucket structure inside `airflow-test-projects-gds-dev` as shown above.
*   Upload your daily order CSV files to the `data/` folder.
*   Upload `orders_data_process.py` to the `spark_code/` folder.

**Step 2: Configure Airflow Variables**
Because this DAG runs on an *existing* Dataproc cluster, you must configure the cluster details in the Airflow UI:
1.  Navigate to **Admin -> Variables** in the Airflow Web UI.
2.  Add a new Variable:
    *   **Key:** `cluster_details`
    *   **Val (JSON format):** 
        ```json
        {
          "CLUSTER_NAME": "your-existing-cluster-name",
          "PROJECT_ID": "project-d1694a9a-9dde-4e3c-974",
          "REGION": "us-central1"
        }
        ```

**Step 3: Deploy the DAG**
*   Upload `airflow_orders_job.py` into the `dags/` folder of your Airflow environment bucket.

**Step 4: DAG Registration**
*   Airflow's scheduler will automatically pick up the new file. Once parsed, the `orders_data_backfilling_dag` will appear on the Airflow Web UI.

**Step 5: Trigger the Pipeline**
*   **Automatic:** If scheduled, it will run automatically using the current system date.
*   **Manual (Backfill):** If you need to process a past file (e.g., `orders_20260922.csv`), click the "Play" button in the UI, select **"Trigger DAG w/ config"**, and pass the JSON parameter:
    ```json
    {"execution_date": "20260922"}
    ```
